# s4 故障排查 · 场景剧本（通用）

> 本文只写**三个品类都成立**的东西。品类差异见 `by_appliance/`：
> `air_conditioner.md`（温度保护、代码体系）、`washer.md`（电/水/排水/门四查）、
> `rice_cooker.md`（判断重心在使用而不是电路）。
> 回答前先确定品类，再读对应文件——**照空调的"滤网 + 室外温度"答洗衣机，是这套知识库最容易犯的错**。

## 五步法（顺序不可调）

```
① 安全判定   命中 safety_redlines → 停机 + 报修，结束
② 正常现象   命中 normal 现象 → 解释清楚，不建单（这一步能挡掉约四成工单）
③ 环境与设置 按品类不同：空调看模式/温度/滤网，洗衣机看门/水压/排水管高度，电饭煲看米水/内锅/蒸汽阀
④ 机型自查   按型号给 1~3 步，用户能自己做的
⑤ 定性报修   两轮无效 / 需要上门 → 建单
```

跳过第 ② 步是最常见的浪费：用户说"空调响"，可能只是制冷剂流动声；说"洗衣机不脱水"，
可能只是衣物太少触发了偏心保护。直接派单，师傅上门啥也没修，成本全吞。

## 三个品类的排查重心完全不同

| 品类 | 用户最常报的 | 真正的第一步 | 最容易被误判成故障的 |
|---|---|---|---|
| 空调 | 不制冷 / 不制热 | 模式与设定温度 | 出风口滴水、自动转送风、关机后 3 分钟不启动 |
| 洗衣机 | 不脱水 / 震动大 / 不排水 | 运输螺栓拆没拆、排水管高度 | Ub 不平衡、泡沫延时、运行中门打不开 |
| 电饭煲 | 饭不熟 / 溢锅 / 不加热 | 米水比例、内锅放没放平、蒸汽阀装没装 | 薄锅巴、咔嗒声、冒白汽、检锅不加热 |

这张表的用法：**先按品类换脑子，再进判定链**。电饭煲的"不加热"里有一大半是内锅没放到位，
而空调的"不制冷"里有一大半是模式选错——两者看着都像硬件故障，都不需要上门。

## 为什么"正常现象"必须单列

三家的说明书里都有一批"这不是故障"的条目，加起来占了故障问询的很大一块：

| 品类 | 现象 | 真相 |
|---|---|---|
| 空调 | 流水声 / 噼啪声 / 冒水雾 | 制冷剂流动、塑料热胀冷缩、冷凝水雾 |
| 空调 | 制热时外机冒蒸汽 | 化霜 |
| 洗衣机 | 面板显示 Ub / 脱水延时 | 偏心保护，不是硬件坏 |
| 洗衣机 | 程序时间突然变长 | 检测到泡沫追加漂洗 |
| 洗衣机 | 运行中门打不开 | 门锁安全保护 |
| 电饭煲 | 锅底薄薄一层锅巴 | 焖饭阶段收水 |
| 电饭煲 | 咔嗒通断声 / 蒸汽阀冒白汽 | 继电器动作 / 正常排气 |
| 电饭煲 | 没放内锅不加热 | 检锅保护 |

这些条目答错的方向是**过度报修**（浪费成本）和**误判为正常**（真故障拖成事故）。
所以每条都有 `severity`，只有 `normal` 才能说"正常"。

## 代码分支

```
用户报代码
├─ 先问清三件事：品类？品牌？几个字符（数字 / 字母 / 是否闪烁）？
├─ 查 05_brand_ref/{brand}/fault_codes.yaml 的对应品类表
│  ├─ 命中且 usable_scope=full  → 按条目给"含义 + 处置"
│  ├─ 命中且 usable_scope=triage_only → 只说类别 + 处置，不说部件名
│  └─ 未命中 → 不猜，走建单（标注"代码未收录 + 代码原文"）
└─ 该品类无代码表 → 直接建单
```

**跨品牌、跨品类套代码都是重大事故来源。** 这里有两个真实的坑：

- 美的空调 E1 是**室内外通信故障**，美的电饭煲 E1 是**底部传感器开路**——同一个品牌、同一个字母，含义无关。
- 小天鹅 E1 是进水超时，西门子 E16 才是门没关好，海尔 E1 是室内环温传感器——三家字母体系各说各话。

品牌表里标了 `usable_scope: triage_only` 的（海尔空调、美的空调、西门子洗衣机），
意思是**只用于内部分诊**：归到哪一类、要不要停机、建单时带什么件。
对外不许把"E1 = 室内环温传感器"这种部件级结论念给用户，因为一旦代码表有偏差，用户会拿着
错误部件名去和师傅对质。

## 三种处置姿态

| 姿态 | 用在哪 | 话术骨架 |
|---|---|---|
| 解释即可 | `severity: normal` | "这是……，属正常，不用修。下次可以……" |
| 引导自查 | `severity: attention` | "先试这一条：……。如果还这样，我马上帮您登记。" |
| 停机报修 | `severity: stop_and_call` | "先断电/关水，不要再开了。我这边帮您登记。" |

安全类（触电、焦味、漏水、AquaStop 底水报警、微压锅强行开盖）一律第三档，
**第一句就是停机动作，不要先解释原因**。

## 话术要点

- 先给"最可能的一条"，不要列 8 种可能让用户自己挑
- 自查步骤最多 3 步，每步要能一句话验证
- 判定报修时把"已排查过的项"一起带进工单，师傅不用重问
- 电饭煲类问题先说清"送修还是上门"——小家电多数是送到特约服务商，承诺"师傅马上到"会翻车

## 不该做的事

- 不做故障原因的确定判断（"肯定是压缩机"/"肯定是主板烧了"）
- 不引导拆机、不动电气、不加冷媒、不撬洗衣机门、不强行开电饭煲盖
- 不在未排除正常现象前就建单
- 不用"应该是……您再试试"拖到第三轮
- 不拿一个品类的排查经验套另一个品类（本文件存在的唯一理由）
